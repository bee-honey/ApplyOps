# ADR-0005: Human approval required before every submission

- Status: Accepted
- Date: 2026-11-18

## Context
Submitting a job application can't be undone and affects the user's reputation. Browser agents can misread forms, and JD/page content may contain prompt injection. Fully autonomous submission optimizes for volume, not quality.

## Decision
- Two required approval gates per application: **documents** (before filling) and **final submission** (with a review-page screenshot).
- Submit is a dedicated step that requires a **signed approval token** generated by the workflow on receiving the `submitDecision` signal. The LLM fallback's tool set has no submit capability, and its click tool refuses submit-like elements.
- The submit step runs at most once (`maximumAttempts = 1`); uncertain outcomes go to reconciliation (see DESIGN §9).
- Possible later relaxation: per-user policy "auto-submit when docs approved, match ≥ X, and no new questions". Not in v1.

## Consequences
- ✅ The user stays accountable and in control; prompt injection can't cause a submission.
- ✅ Clear safety boundary to explain in interviews.
- ⚠️ Throughput is limited by user response time (fine: quality over volume).
- ⚠️ Extra Telegram round-trip per application.

## Alternatives considered
- **Approve documents only, auto-submit:** faster, but form-fill mistakes go out unseen.
- **Fully autonomous:** rejected for safety and quality reasons.
